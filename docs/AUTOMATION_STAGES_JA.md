# 実機自動化の段階検証

操作者の指示により、ゲーム内操作は各段階で許可を得てから実行します。
現段階の許可を次の段階や別のボタンへ拡張しません。各段階はまずdry-runで操作列を確認します。
判定不明・映像停止・接続断は停止し、自動リセットしません。

## 段階1：Bボタン1回 — 成功

2026-11-13、操作者が手動で通常メニューを開き、Bを1回だけ0.08秒押して離す試験を明示的に許可。
送信前に日本語USUMの通常メニューを映像で確認し、3か所のメニュー画像領域と両画面の鮮度を再確認しました。

dry-runでパケットを生成した後、実機へB押下・B解放・物理制御へ戻す20バイトパケットを各1回だけ送信しました。
他のボタン、タッチ、リセットは送信していません。送信間隔はログ上で約0.084秒です。
送信前の通常メニューが送信後に閉じ、フィールド／ロトム図鑑へ戻ることを受信画像で確認。
操作者も「自分では操作せず、メニューが自動で閉じた」と確認しました。
入力後も上15枚・下14枚の完全画面を受信し、10.032秒の試験を正常終了しました。

これはOld 3DS＋HIMEM＋USUMでB1回が反映され、その前後で映像が届いたという限定した確認です。
すべてのキーの安定性・リセット継続・日本語ギフト認識が完了したとは扱いません。
実機のlive解禁記録は作成していません。

## 段階2：基本操作 — 11押下完了、短時間の画面反応を確認

開始状態は、操作者が手動で開いた通常メニューの「ポケモン」選択。
予定操作は「右→左→下→上」を2周し、Aでポケモン一覧を開き、Bで通常メニューへ戻り、
もう一度Bでフィールドへ戻る計11押下です。各キーは1回0.08秒。
各操作後に期待したカーソル／画面遷移を確認してから次へ進みます。不明なら止めます。
セーブ、道具使用、受け取り、リセットは含みません。
この操作列のdry-runは送信0パケットで実施し、33データグラム相当を検査しました。
操作者が11押下を許可した後、2026-11-14に実施しました。
各入力の前後で映像とメニュー／カーソルを照合し、右・左・下・上を2周、A、B、Bを
合計11回、各1回だけ送信しました。ログで33データグラム（押下・解放・物理制御復帰）を確認。
ポケモン一覧が開き、通常メニューへ戻り、最後に安定したロトム図鑑へ戻った受信画像を確認しました。
最終の受信のみの確認は3.075秒、上6枚・下5枚でした。セーブ・リセットは未実施です。

これは連続11操作を無中断で完走した試験ではありません。7回目後のカーソル照合信頼度、
9回目後のフレーム鮮度により停止し、保存画像／新しい受信で実状態を確認して残りだけを再開しました。
送信済みキーの自動再試行はしていません。通信の長時間安定性とリセット復旧は未検証です。
また、今回の反応は受信映像による確認であり、段階1のような操作者の追認はまだありません。
私有証跡は `captures/stage2-summary-20261114.json` と参照先フォルダに保存しています。

受信時刻の不具合も修正しました。TCP受信が前のパケットの末尾と次のパケットの先頭を含む場合に、
最初のパケットの時刻を次々に継承していたため、各パケットの先頭バイトの受信時刻を個別に保持します。
断片化・結合した受信の回帰テストを追加し、45テストが通過。2秒の鮮度／組立上限は変更していません。
実機の一時的な遅延は修正後にも観測されており、すべての停止をこの不具合のせいとは扱いません。

## 段階3：レポート保存・ソフトリセット・復帰 — 未着手

「レポート保存」は診断ログの保存ではなく、**ゲーム内レポート＝セーブの完了**を確認します。
操作者からその完了とリセット試験の許可を得るまで実行しません。
現行の厳選処理は通信断時に停止し、自動再接続はしません。
リセット後の映像・操作の復帰を試す場合は、回数と対象を限定した独立した試験として準備し、
不明状態でリセットを繰り返す仕様にはしません。
